# 原型验收与发布规范

## 1. 验收前提

一个原型页面交付前，必须同时满足：

- 页面能从「系统设置」打开，导航分组和标题正确。
- 页面加载无空白、无未处理异常；异步加载有占位。
- 主要交互可用：搜索、筛选、弹窗、表单、开关、状态切换。
- 布局在桌面和 900px / 680px 两个断点下不溢出、不重叠。
- 空状态、加载状态、错误状态都有明确反馈。
- 浏览器控制台没有报错和未处理 Promise。
- `npm run build` 通过，类型检查没有报错。
- 没有修改其他需求的原型；没有未确认的删除、重命名或跨需求移动。
- 没有新增未确认的依赖、路由或构建配置。

## 2. 本地预览确认

1. 运行 `npm run build`，再运行 `npm run dev`。
2. 在真实浏览器中打开页面，按第 1 节逐项检查。
3. 把页面地址、检查项和结果发给用户。
4. 由用户确认视觉、交互和业务表达是否符合预期。
5. 用户确认前，不进入发布流程。

## 3. 发布授权

- 只有用户在当前对话中明确说“发布”“部署”或“上传”时，才允许执行 PinMe 发布。
- 之前的授权不延续到新的发布；每次发布都要重新确认。
- 默认目标域名来自 `.pinme.json` 的 `domain`；不要在未确认的情况下换域名或使用 `PINME_DOMAIN` 覆盖。
- 首次没有 `.pinme.json` 时，停下来向用户确认固定域名，不要自行创建或猜测。
- 必须完整构建后上传；不要使用 `npm run deploy:skip-build`，除非用户明确要求复用已有 `dist/`。
- 不要自动发布、定时发布、在后台发布或在验证未完成时提前上传。
- 发布属于覆盖固定域名的操作；本项目没有版本管理，覆盖后无法从项目内回滚。

## 4. 发布后验证

发布命令返回成功不代表发布成功，必须继续验证：

- 输出中拿到访问地址或 CID；没有拿到时按失败处理。
- 打开 `https://<domain>.pinme.eth.limo`，确认首页能加载。
- 刷新页面，确认仍能加载（`base: './'` 生效，资源不 404）。
- 打开本次修改的页面，检查主要交互和控制台。
- 检查静态资源（JS/CSS/图标）返回 200。
- 记录发布时间、域名、验证结果和未覆盖项。

任何一项失败都不能声称发布成功；先定位原因，再决定是否重试。

## 5. 发布失败处理

- 构建失败：修复后重新构建，不上传旧 `dist/`。
- PinMe 未登录或 AppKey 无效：提示用户完成认证，不读取或记录令牌。
- 没有拿到 CID/URL：按失败处理，不重试覆盖其他域名。
- 上传后页面 404 或资源 404：检查 `base: './'`、`dist/index.html` 和上传目录。
- 发布后出现严重问题：立即告知用户影响范围；没有版本管理时不要假装能回滚，优先修复后重新发布，或按用户指示处理。

## 6. superPM MCP 回写

- 默认不回写任何 superPM 正式数据。
- 只有同时满足以下条件才允许回写：
  1. 用户明确要求回写；
  2. 发布成功且访问链接已验证有效；
  3. 回写内容经过用户确认。
- 回写必须通过 superPM 的业务服务或 MCP 工具，不允许直接改数据库、文件或审计表。
- 只写与本次原型发布直接相关的内容；不写入令牌、绝对路径、堆栈或未确认的结论。
- 回写失败时如实报告，不重复写入或绕过服务。

## 7. 不做的发布相关事项

- 不建立版本号、标签、变更日志或发布分支。
- 不创建 `release/`、`v1/`、`backup/` 等目录。
- 不向模板仓库提交或推送；个人原型不进入版本管理。
- 不把 PinMe 发布做成自动脚本在后台运行；`npm run deploy` 只能由人明确触发。
